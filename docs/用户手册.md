# 金策 BizGold 用户手册

## 1. 安装与启动

任意一台电脑（Windows 10/11、macOS、Linux）三步跑起来：① `git clone` 后运行一键体检 `powershell -ExecutionPolicy Bypass -File scripts\doctor.ps1`（Linux/macOS：`bash scripts/doctor.sh`），按 FAIL 行给出的命令补齐 Node / pnpm / Python / Git Bash / Office 或 LibreOffice / 中文字体；② `scripts\setup.ps1`（或 `scripts/setup.sh`）安装依赖并构建；③ 填密钥后 `pnpm start`（Windows 长期运行用 `scripts\service.ps1 -Install`）。体检脚本可以反复跑，直到全部 OK。

1. 前置：Node.js ≥ 20、pnpm、Python ≥ 3.10（Anaconda 可）、Git for Windows（提供 Bash 工具；没有时自动改用 PowerShell 工具）。可选：Word / WPS 或 LibreOffice（用于 docx → PDF 与页数核验）。
2. 运行 `powershell -ExecutionPolicy Bypass -File scripts\setup.ps1`（Linux/macOS：`bash scripts/setup.sh`）。
3. 密钥：任选其一——系统环境变量 `BIZGOLD_API_BASE_URL`（例如 `https://llm.goaichat.top`，不带 `/v1`）与 `BIZGOLD_API_KEY`；或启动后在「设置」页填写并保存（写入 `%USERPROFILE%\.bizgold\settings.json`，不在项目目录内）。
4. 启动：`pnpm dev`（前端 5173 + 后端 5178，开发热更新）或 `pnpm build; pnpm start`（单端口 5178）。
5. 常驻（推荐，Windows）：`pnpm build` 后运行 `powershell -ExecutionPolicy Bypass -File scripts\service.ps1 -Install`，服务端注册为计划任务 `BizGoldServer`（开机登录自动启动、关掉终端也不会停，日志在 `%LOCALAPPDATA%\BizGold\server.log`）；`-Status` 看状态、更新代码并重新 `pnpm build` 后用 `-Restart`、`-Uninstall` 删除。长时间运行（一次完整生成 2–4 小时）请用这种方式，不要挂在会被关掉的终端里。
5. 打开浏览器 → 顶栏健康点全绿（API / Python / PDF 转换器）即可使用；「设置 → 测试连接」可拉取网关模型列表。

## 2. 新建一个项目

「新建项目」三步：
1. **赛道与组别**：品牌策划 / 创业计划 / 数字营销 / 案例分析 / 会奖旅游；卡片显示评分权重与必备要素。
2. **项目信息**：作品名、团队名（匿名制下代替院校）、策划对象（品牌 / 项目 / 案例企业 / 年会客户）、是否命题企业（可从名单选）、地区与行业、项目简介（越具体越好：现有产品、价格、渠道、已有资产、目标）、团队成员（角色 / 专业 / 特长，不填姓名院校）、上传资料（企业介绍、年报、调研数据、命题文件等，PDF/Word/Excel/CSV/图片，自动预读）。
3. **生成参数**：各角色模型（默认主代理 deepseek-v4-pro，评委用 kimi-k3 / glm-5.3 / qwen3.8-max 形成多模型评委团）、调研模式（示例数据 / 仅用我的资料）、正文目标页数、讲稿时长、评审轮数、目标分。

点击「开始生成」。一次完整运行通常 40–120 分钟（取决于模型速度与评审轮数）。

## 3. 运行中

- **运行控制台**：9 个阶段进度（读题解析 → 调研 → 策略 → 财务 → 图表 → 撰写 → 路演 → 评审 → 打包），主代理与各子代理分泳道显示文本、工具调用与文件写入；Token 与费用估算实时更新；可「停止」，之后可「续跑」（从当前阶段继续）。
- 中途可以关掉浏览器，服务端继续运行；重新打开自动回放事件。

## 4. 产出与评审

- **产出物**：左侧文件树 + 右侧预览（Markdown / 图片 / PPT 预览 / Excel 表 / PDF），常用产出置顶（策划书 docx/pdf、路演 pptx、财务模型 xlsx、讲稿、题库、提交包 zip）。
- **评审**：最新轮总分与目标线、维度雷达、三位评委意见与前五条修改建议、机器检查表（pass / warn / fail）、硬门槛、跨材料一致性、轮次历史。
- **数字账本**：所有关键数字（收入、预算、样本量、SOM…）的值、来源与一致性标记。
- **修改对话**：输入指令（例如“把第 5 章 KOL 分层表改为 4 层并补预算来源”“讲稿压到 8 分钟”），系统在原会话上修改并重新渲染与检查。

## 5. 提交前必须由团队完成的事

1. **替换示例数据**：按 `08_提交包/数据真实性清单.md` 逐条替换为真实调研结果（问卷与访谈提纲已在 `01_调研/调研工具包/`），重跑图表与文档（修改对话里说“用真实调研数据更新”）。
2. **填写学校名**：文件名中的“学校名称”占位按赛区命名规则替换；正文仍保持匿名。
3. **补设计稿**：品牌元素章节给出的是设计说明与规范表，LOGO / 包装等图形请由团队设计后插入。
4. **声明与授权**：打印 `08_提交包/` 中的原创性声明、版权声明、企业授权书，手写签名 + 指印，企业盖章。
5. **录制视频**：按 `06_路演/视频分镜.md` 录制 10 分钟陈述视频（开头 3–5 名队员真人出镜，画面不得出现校徽校名）。
6. **通读修改**：细则禁止“完全使用 AI 工具创作”，请逐章修改确认，使之成为团队自己的作品。

## 6. 常见问题

| 问题 | 处理 |
|---|---|
| 健康点 API 红 | 检查 Base URL（不带 /v1）与密钥；「设置 → 测试连接」查看错误；网络不通时切换备用地址 |
| Python 依赖缺失 | `python -m pip install -r agent\toolkit\requirements.txt`；设置页可指定解释器路径 |
| 没有 PDF 转换器 | 产出仍有 docx，用 Word「另存为 PDF」；页数以 PDF 为准 |
| 运行中断 | 项目页「续跑」；若网关报 400，可在设置里勾选“禁用 thinking / 禁用实验性 beta” |
| 评分达不到目标 | 看评审页“前五条修改建议”，用修改对话逐条处理；补充真实资料会显著提高“现状分析 / 一手资料”维度 |
| 图表中文乱码 | 设置页「字体检查」确认已安装中文字体（Windows 默认有微软雅黑 / 宋体） |

## 7. 数据与隐私

密钥只存在本机设置文件或环境变量；所有产出保存在 `workspace/<项目 id>/`；检索与抓取只请求公开网页；不上传任何文件到第三方（模型网关除外）。
